# 数据埋点流程图(Excalidraw)

数据埋点标准流程的可视化项目,使用 [Excalidraw](https://excalidraw.com) 绘制,并以「电商 App 优化支付转化率」为贯穿示例。

## 目录结构

```
data-tracking-flow/
├── README.md                        # 本说明
├── index.html                       # 内嵌 Excalidraw 的本地查看页(双击即可打开,顶部可切换两张图)
├── docs/
│   └── 埋点方案.md                  # 流程第②步的产出物:完整事件设计方案
└── static/
    ├── 数据埋点流程.excalidraw       # 图1 源文件:埋点八步闭环(可编辑,唯一事实来源)
    ├── 漏斗去重流程.excalidraw       # 图2 源文件:漏斗去重判定流(可编辑,唯一事实来源)
    ├── 数据埋点流程-预览.png         # 图1 静态预览图(可直接引用到文档/PPT)
    └── 漏斗去重流程-预览.png         # 图2 静态预览图
```

## 快速查看

| 方式 | 操作 | 说明 |
|------|------|------|
| 本地查看页 | 双击 `index.html` | 内嵌 Excalidraw 渲染,顶部按钮切换「埋点主流程 / 漏斗去重」两张图,可缩放、框选、二次编辑;需联网加载渲染库,加载失败时页面会提示并给出静态图链接 |

## 流程说明

主线 8 步 + 红色虚线「新一轮循环」回到第 ① 步,构成闭环。其中第 ② 步「设计事件方案」的正式产出物见 [docs/埋点方案.md](docs/埋点方案.md)(含指标口径、公共属性、6 个事件明细、验证清单与告警规则):

1. **定目标** — 从业务问题出发,明确分析目标与衡量指标(示例:支付成功率 40% → 60%)
2. **设计事件方案** — 输出事件表 / 埋点字典:事件名 + 属性 + 命名规范(示例:6 个核心事件)
3. **选埋点方式** — 服务端埋点(关键交易)、代码埋点(核心行为)、全埋点(通用浏览)组合使用
4. **开发接入** — 集成数据 SDK,按方案实现采集代码
5. **验证** — 调试模式走通全流程,核对事件触发顺序与属性完整性
6. **监控质量** — 盯上报量、字段完整率,配告警
7. **分析应用** — 漏斗/留存/路径分析,定位问题并产出结论(示例:漏斗定位到支付签名 bug)
8. **迭代** — 带着新分析需求补充埋点,进入下一轮循环

## 埋点方式速查

| 方式 | 特点 | 适用 |
|------|------|------|
| 代码埋点 | 精准、可控 | 核心业务事件 |
| 可视化埋点 | 界面圈选配置 | 简单点击事件,运营自助 |
| 全埋点(无埋点) | SDK 自动采集 | 通用浏览行为打底 |
| 服务端埋点 | 准确性最高 | 交易等关键链路 |

## 漏斗去重(第二张图)

回答"用户刷新、回退、重复上报时,漏斗为什么不会数错"。一条事件要连过四关才被计入漏斗:

1. **只保留漏斗步骤事件**——4 个业务事件,其余不进漏斗;
2. **确定去重键**——用户级步骤按 `user_id`,订单级步骤按 `order_id`;
3. **首次出现才计数**——同一键在此步骤只取第一次,刷新 ×5 也只算 1 人;
4. **顺序 + 会话窗口**——须晚于上一步首次发生时间、间隔 ≤ 30 分钟,乱序/跨会话丢弃。

示例口径:进购物车 5 人 → 点结算 4 人 → 提交订单 3 单 → 支付成功 2 单(整体转化 40%)。与 [docs/埋点方案.md](docs/埋点方案.md) 第 2 节的指标口径一一对应。

## 修改指引

- **改图**:编辑 `static/数据埋点流程.excalidraw`(在 excalidraw.com 或 VS Code 插件中修改后保存)。
- **注意**:`index.html` 中的场景是源文件的内嵌快照(为了让双击打开、无需本地 HTTP 服务)。源文件修改后,index.html 不会自动同步——重新生成一次即可(把新的 .excalidraw JSON 替换页面中的 `SCENE` 常量),或继续用 excalidraw.com 打开最新源文件。
